# Local image service

The CLI emits photograph URLs by default. The companion service makes them
available to Obsidian Desktop on the same Mac. Videos, GIFs, image documents,
web previews, paid and expiring media are outside this version.

## Install and start

One Homebrew Formula, `octolab/tap/indexit`, installs both the CLI and its
service definition. They use the same binary and update together. For a new
installation, run `brew install --formula octolab/tap/indexit`.

If you installed the previous Cask, migrate once after the Formula is published:

```sh
brew update
brew uninstall --cask octolab/tap/indexit
brew install --formula octolab/tap/indexit
```

Do not use `--zap`: keep your Telegram configuration and saved photographs.
Then configure networking explicitly once:

```sh
sudo sh "$(brew --prefix octolab/tap/indexit)/libexec/macos-service-network.sh" install
brew services start octolab/tap/indexit
curl -4 http://indexit.local/
```

The service uses IPv4 loopback. On macOS, `curl -4` avoids waiting for an IPv6
mDNS answer for `.local`; image URLs in Obsidian remain unchanged.

The administrator step adds a marked `127.0.0.1 indexit.local` hosts entry and a
loopback-only PF rule forwarding port 80 to 17840, restored at boot by a small
system networking job. It leaves the main PF ruleset intact. The image service
runs as your normal user and listens only on `127.0.0.1:17840`. Installing the
package alone neither configures networking nor starts a privileged image service.
Custom PF configurations or another application already using local port 80 need
manual resolution. While the rule is active, local traffic to `127.0.0.1:80`
belongs to indexit; do not start another server on that address. Do not run
`sudo brew services`.

The service reads the same `~/.config/indexit/.env` and Telegram session as the CLI.
The service ignores working-directory `.env` files and uses the shared config
directory; explicit `--env-file` and `INDEXIT_ENV_FILE` still override it. Ordinary
CLI commands retain their working-directory lookup. Use the same account and
data-directory settings for both processes. Sign in through
the CLI before requesting an uncached photograph. No separate HTTP proxy is needed.

## Storage and availability

Data lives in `~/.local/share/indexit`, or `$XDG_DATA_HOME/indexit`.
`INDEXIT_DATA_DIR` overrides the complete directory. Keep the CLI and service on
the same directory. Source metadata and image bytes are separate private files.
There is no automatic eviction or storage limit: disk use grows as images are read.
Keep a backup if a local copy may become the only surviving photograph.

A saved image needs no Telegram session or network. A cold request waits for any
running CLI Telegram operation, for at most two minutes; retry a failed request.
Cached requests continue during that wait. Concurrent downloads of one photo are
coalesced across processes and incomplete files are never published.

URLs contain no secret token. Any local client knowing a URL can read its image.
They are not promised to work from a phone, another machine or a web page that
blocks local HTTP. Clearing browser cache does not delete the saved photograph.

If Obsidian opens a note before the service is ready, failed image elements may
remain visible after the service starts. Check `curl -4 http://indexit.local/`,
then reopen the note or switch to reading view to reload its images.

## Upgrade, stop and remove

```sh
brew update
brew upgrade --formula octolab/tap/indexit
brew services restart octolab/tap/indexit
brew services stop octolab/tap/indexit
```

Old URLs, configuration and saved data survive updates and restarts. Before
removing the Formula, remove its system networking explicitly:

```sh
sudo sh "$(brew --prefix octolab/tap/indexit)/libexec/macos-service-network.sh" uninstall
brew services stop octolab/tap/indexit
brew uninstall --formula octolab/tap/indexit
```

Uninstall preserves photographs and source metadata. Explicitly remove files
under `images/` only when you intend to discard those copies; leave `sources/`
and your Telegram configuration alone. Deleted remote sources cannot be recovered.

## Local development and Linux

```sh
go build -o ./bin/indexit .
./bin/indexit service run --listen 127.0.0.1:17840
```

For a temporary transport check, replace the URL origin with
`http://127.0.0.1:17840`. This is not the permanent URL stored in notes.
The ordinary Linux CLI still works; automatic Linux hostname, port and service
setup is outside this iteration. Root `/` is a health page without an image index.
