# v0.1.1 — One dialog, one entry.

`telegram fetch dialogs` now emits each conversation once per run. Pinned dialogs no longer reappear on later pages, and overlapping pages cannot produce duplicate records for the same `uid`.

## Pick a conversation without duplicate rows

Pipe the dialog list into fzf as before:

```sh
indexit -q telegram fetch dialogs \
  | jq --unbuffered -r '[.uid, .title // .username // .uid] | @tsv' \
  | fzf --delimiter '\t' --with-nth 2..
```

- `--limit` counts unique conversations; repeated records do not use up the limit.
- Different conversations with the same title remain separate. Deduplication uses the full `uid`, so `chat:42` and `channel:42` are distinct.

## Telegram compatibility

Updated Telegram protocol support to API layer 229.

**Upgrade:** on macOS, run `brew update` followed by `brew upgrade --cask octolab/tap/indexit`. For a manual installation, use a [v0.1.1 release archive](https://github.com/octopot/indexit/releases/tag/v0.1.1). Run `indexit version` to check the installed version.
