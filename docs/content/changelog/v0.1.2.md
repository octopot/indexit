# v0.1.2 — One message, one entry.

`telegram fetch messages` and `telegram fetch media` now process each message ID at most once per run, including when fetching a forum topic. Repeated IDs within a page or across overlapping pages no longer produce duplicate records.

## Keep limits and downloads accurate

- `--limit` counts unique results; repeated message IDs do not use up the limit.
- Media exports avoid repeated downloads and manifest records, including with `--overwrite`.
- Different messages with identical text or media remain separate. Album frames with different message IDs are preserved.

[Explore messages →](/guide/messages/) · [Save topics and media →](/guide/media/)

## Stop when history cannot advance

If Telegram returns a nonempty history page without older message IDs to continue from, the command exits with an error instead of looping or reporting the export as complete. This applies to both message and media exports.

**Upgrade:** on macOS, run `brew update` followed by `brew upgrade --cask octolab/tap/indexit`. For a manual installation, use a [v0.1.2 release archive](https://github.com/octopot/indexit/releases/tag/v0.1.2). Run `indexit version` to check the installed version.
