# v0.4.1 — Every dialog, its own date.

`telegram fetch dialogs` now dates each conversation by its own last message, so the list is complete: no dialog is skipped between pages, and every `last_message_at` belongs to its own record.

## A complete dialog list

```sh
indexit -q telegram fetch dialogs | jq -r '[.last_message_at, .uid] | @tsv'
```

- Telegram numbers the messages of every channel from 1, so two channels on one page can have last messages with the same number, such as channels with nothing but their creation. indexit could take the date of one for the other.
- A wrong date could also send the next page to the wrong point in your list and skip the dialogs in between. Each dialog is now matched with the last message of its own chat.

## Clearer flags

- An invalid flag value names what is expected, such as `must be an integer`, instead of a parse error.
- `--help` shows that on/off flags also take an explicit value: `--quiet[=true|false]`.

## Telegram compatibility

Updated Telegram protocol support to API layer 232.

## Security

- indexit builds with fixed versions of the compression libraries its Telegram connection uses: a crafted compressed response could crash it or make it allocate excessive memory.

**Upgrade:** on macOS, run `brew update` followed by `brew upgrade --formula octolab/tap/indexit`. For a manual installation, use a [v0.4.1 release archive](https://github.com/octopot/indexit/releases/tag/v0.4.1). Run `indexit version` to check the installed version. If you use the agent skill, [replace it](/guide/agents/#keep-it-in-step) with the new binary’s copy.
