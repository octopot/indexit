# v0.2.2 — Cards for people, too.

`telegram fetch peer` now describes users and bots in full, not only channels and groups: the bio, the personal channel, the birthday, a business account's address and hours, and a bot's description and commands. The local peer cache now belongs to one account, so after you switch accounts indexit never sends another account's addresses.

## Describe people and bots

```sh
indexit -q telegram fetch peer @example_person @example_bot \
  | jq '{uid, peer_type, title, about, personal_channel, bot, error}'
```

- A user or a bot is a full card, not an error. The `not_channel` error is gone: to keep only channels and groups, filter by `peer_type`.
- `about` is the bio. `personal_channel` names the channel shown on the profile, with its `uid`, `title`, and `username`, shaped like `linked_chat`.
- Names, the phone number, the birthday (with or without the year), the business location, hours, and intro, the Stars rating, and the price of a paid message appear when Telegram returns them. What privacy settings hide is absent, without an error.
- A bot card has `bot` with the description, commands, privacy policy link, and what the bot may do in groups. A cached `user:<id>` reports `bot` for a bot too.
- If the full request fails, the card keeps the identity indexit already knows, with `error.code: "rpc"`.
- A numeric `user:<id>` known only from a passing mention, such as a message in a large group, reports `cold_peer` but keeps its `uid`, `title`, and `username`.

## Keep each account's peer cache to itself

- The peer cache records the account it belongs to. A cache written for another account, or by an earlier version, starts empty with a warning that says to run `fetch dialogs`; `-q` hides the warning, not the reset.
- Signing in again as the same account keeps the cache. While the session is unchanged, the check costs no request.
- If indexit cannot tell the account, the command runs without the cache and leaves the file as it was.
- `auth status` shows the peer cache and the account it belongs to.

**Upgrade:** on macOS, run `brew update` followed by `brew upgrade --cask octolab/tap/indexit`. For a manual installation, use a [v0.2.2 release archive](https://github.com/octopot/indexit/releases/tag/v0.2.2). Run `indexit version` to check the installed version. The first fetch after the upgrade starts the old peer cache empty: run `indexit telegram fetch dialogs` once to refill it. If you use the agent skill, [replace it](/guide/agents/#keep-it-in-step) with the new binary’s copy.
